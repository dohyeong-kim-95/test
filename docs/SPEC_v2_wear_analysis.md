# 거울 전신샷 기반 착용 패턴 분석 — MVP 스펙

## 1. 목적

전신거울 앞에서 찍은 사진만 쌓으면, 옷장을 따로 등록하지 않아도
**어떤 옷을 언제, 얼마나 입었는지**와 **세탁이 필요한지**를 자동으로 정리한다.

## 2. 사용 시나리오

1. 사용자가 매일 외출 전 거울 앞에서 전신 사진을 찍는다 (MVP는 휴대폰).
2. 사진을 지정된 폴더에 복사한다.
3. 로컬 웹서버를 실행하고 브라우저에서 갤러리를 연다.
4. **다시 분석** 버튼을 누르면 새 사진이 처리되고 옷 목록, 착용 통계, 세탁 상태가 갱신된다.
5. 빨래를 한 옷은 갤러리에서 **빨았음**을 누른다.

## 3. MVP 범위

| 포함 | 제외 (추후) |
|---|---|
| 사진 폴더 처리 (새 사진만) | 거울 카메라 실시간 촬영, 웹 업로드 |
| 상의·하의·원피스·외투 분리 | 신발, 가방, 액세서리 |
| 옷 자동 묶기 (옷장 등록 없음) | 묶음 합치기/나누기, 옷 이름·종류 수정, 숨기기 |
| 착용 통계 | 옷장 옆모습 사진 매칭 |
| 착용 횟수 기반 세탁 추정 | 옷별 세탁 기준 설정, 개인 세탁 주기 학습 |
| 로컬 웹 갤러리 + 빨았음 버튼 | 코디 추천 |

## 4. 입력

- **사진 폴더**: jpg / png. 한 장에 한 사람, 전신이 보이는 사진.
- **촬영 시각**: EXIF 촬영 시각을 쓰고, 없으면 파일 수정 시각을 쓴다.
- **설정 파일**: 사진 폴더 경로, 세탁 기준 횟수, 묶기 기준값.

## 5. 처리 흐름

| 단계 | 내용 | 후보 기술 |
|---|---|---|
| 1. 새 사진 찾기 | 아직 처리하지 않은 사진만 고름 | 처리 기록 (DB) |
| 2. 옷 영역 분리 | 상의·하의·원피스·외투 영역을 잘라냄 | SegFormer 의류 분할 모델 |
| 3. 벡터화 | 잘라낸 옷 이미지를 숫자 벡터로 변환 | SigLIP 2 (기준선), Marqo-FashionSigLIP·Kanana-2 비전 인코더 tiny (비교 후보, 5-1절) |
| 4. 종류 판별 | 티셔츠/셔츠/니트/바지/청바지/치마/원피스/외투 | SigLIP 계열 제로샷 분류 |
| 5. 옷 배정 | 기존 옷 중 가장 비슷한 것과 거리가 기준값 이내면 그 옷, 아니면 새 옷으로 등록 | 최근접 대표 벡터 비교 |
| 6. 착용 기록 | 날짜별로 어떤 옷을 입었는지 기록 | — |
| 7. 통계·세탁 계산 | 아래 6, 7절 참고 | — |

### 5-1. 벡터화 모델 후보

| 모델 | 크기 | 장점 | 확인할 점 |
|---|---|---|---|
| SigLIP 2 (기준선, Google 2025.02) | 약 1~4억 | 이미지끼리 비슷한 정도를 비교하도록 학습됨, 텍스트로 종류 판별 가능 | — |
| Marqo-FashionSigLIP (2024) | 약 2억 | 패션 이미지로 추가 학습됨, 텍스트로 종류 판별 가능 | 거울 셀카처럼 실생활 사진에서도 좋은지 |
| Kanana-2 비전 인코더 tiny | 9,800만 | CPU에서 가볍게 돌아감, 상업 이용 가능 | 텍스트 인코더가 없으면 4단계(종류 판별)에 못 씀 |
| Kanana-2 비전 인코더 medium | 4억 2,600만 | 카카오 자체 평가에서 SigLIP 2 등보다 우수 | CPU 속도 |

- Kanana-2 비전 인코더는 언어모델과 붙여 쓰는 용도로 나온 모델이다. 공개된 평가도 질의응답, 문자 인식, 문서 이해 위주라서, **옷끼리 비슷한 정도를 비교하는 데 좋은지는 직접 확인해야 한다.**
- 방법: 같은 사진으로 세 모델의 묶기 결과를 비교하고, 10절 성공 기준에 더 가까운 쪽을 고른다.
- 4단계(종류 판별)는 텍스트로 분류해야 하므로 SigLIP 계열(SigLIP 2 또는 Marqo-FashionSigLIP 중 더 나은 쪽)을 쓴다.

**규칙**
- **하루의 기준은 새벽 4시**다. 새벽 0~4시에 찍은 사진은 전날로 본다.
- 같은 날 같은 옷이 여러 장에 나오면 착용 1회로 센다.
- 하루에 옷을 갈아입어 사진이 여러 장이면, 그날 나온 옷을 **모두** 착용으로 센다.
- 외투에 가려진 안쪽 옷은 기록하지 않는다. **보이는 옷만** 기록한다.
- 옷 영역을 못 찾은 사진은 건너뛰고 로그에 남긴다.
- 옷 ID는 한번 정해지면 바뀌지 않는다 (5단계 방식). 세탁 기록이 옷 ID에 연결되기 때문이다.

## 6. 착용 통계

옷마다 다음을 계산한다.

- 착용 횟수, 첫 착용일, 마지막 착용일
- 미착용 일수 (오늘 − 마지막 착용일)
- 요일별 착용 분포
- 자주 함께 입은 옷 (같은 날 함께 나온 옷 조합)

## 7. 세탁 추정

마지막 세탁 이후 착용 횟수가 종류별 기준에 도달하면 **세탁 필요**로 표시한다.

| 종류 | 기준 (기본값, 설정 파일에서 변경) |
|---|---|
| 티셔츠, 셔츠 | 1회 |
| 니트 | 3회 |
| 바지, 치마, 원피스 | 5회 |
| 청바지 | 7회 |
| 외투 | 20회 |

갤러리에서 **빨았음**을 누르면 그 시각을 세탁 기록으로 저장하고, 이후 착용만 다시 센다.

## 8. 출력 (로컬 웹 갤러리)

- **옷 목록 화면**: 옷마다 대표 이미지, 종류, 착용 횟수, 마지막 착용일, 세탁 상태, **빨았음** 버튼
- **옷 상세 화면**: 그 옷이 나온 사진 모음 (잘 묶였는지 눈으로 확인용), 착용 날짜 목록
- **다시 분석** 버튼
- 데이터 내보내기: `garments.csv` (옷별 통계), `wear_log.csv` (날짜, 사진, 옷 ID)

## 9. 비기능 요구사항

- Python으로 작성하고, **GPU 없는 일반 PC의 CPU**에서 돌아가야 한다.
- 모든 처리는 로컬에서 하며, 사진을 외부로 보내지 않는다. 웹서버는 내 컴퓨터에서만 접속된다.
- **원본 사진은 그대로 둔다.** 프로그램은 원본을 수정하거나 지우지 않는다.
- 처리 결과(잘라낸 이미지, 벡터, 기록)는 파일로 저장해 다시 쓴다.
- 새 사진 10장을 몇 분 안에 처리할 수 있어야 한다.

## 10. 성공 기준

사진 2주치(15장 이상)로 확인한다.

- 옷 영역 분리: 사진의 90% 이상에서 옷을 찾는다.
- 자동 묶기: 옷 상세 화면을 봤을 때 80% 이상의 옷이 한 벌의 사진만 담고 있다.
- 착용 기록: 실제로 입은 옷 기록과 비교해 80% 이상 일치한다.

## 11. 미결정 사항

- 자동 묶기 기준값: 실제 사진으로 조정이 필요하다.
- 묶기 오류 보정이 없으므로, 오류가 많으면 합치기/나누기를 다음 단계에 넣는다.
